# Rainbow Gum 0.15.0

This release is effectively **1.0.0-RC4**. The headline is a **new property layout**:
component settings now live under the appender or route that uses them, global switches
became enums resolved once per configuration, and booleans parse strictly. Configuration
written for 0.14 needs updating; see [Breaking changes](#breaking-changes). Alongside that
come a lot of new features: OTLP export without the OpenTelemetry SDK, logfmt and JSON
encoders in core, a configurable TTLL with color themes, a level file that changes levels
without a restart, and checks that catch misspelled or unused property keys.

## New features

- **`rainbowgum-otlp`:** OTLP log export without the OpenTelemetry SDK. An `otlp` encoder
  writes OTLP/JSON lines (the Collector's `otlpjsonfile` format) and an `otlp` output posts
  batches to `/v1/logs` as protobuf or JSON, optionally gzipped, with retries and backoff.
  Protobuf is encoded by hand, so there is no protobuf dependency. `OTEL_*` environment
  variables are only read with the opt-in `environmentVariables` property.
- **`rainbowgum-opentelemetry`:** adds `traceId` and `spanId` from `Span.current()` to every
  event, for applications using the OpenTelemetry API, SDK or agent directly.
- **logfmt in core:** `encoder.uri=logfmt` writes one `key=value` line per event, the shape
  of Go's `log/slog` text handler, which Loki and Vector parse directly.
- **json5 encoder in core:** `encoder.uri=json5` switches a TTLL application to structured
  output with no extra module. `format=json` writes plain JSON, `prettyPrint` selects
  `level_padding`, `spacing`, `full` or `off`, and key values named like a field go in a
  nested `keyValues` object instead of being dropped or duplicated.
- **Configurable TTLL:** each part (`timestamp`, `thread`, `level`, `logger`, `keyValues`)
  can be set with properties, much like slf4j-simple's options, without the pattern module.
  Key values are now shown by default, percent encoded.
- **Color themes:** TTLL, logfmt and json5 color with a theme: `rainbowgum` (the default,
  matching the default pattern), `spring`, `one_dark` and `darcula`. `color` decides whether
  to color (`default`, `detect`, `force`, `off`) and `theme` which colors. Custom themes are
  built with `TTLL.ColorTheme.builder(name)` and can be chosen by name from the service
  registry.
- **Key values formatting:** `KeyValuesFormatterBuilder` formats key values as percent
  encoding, JSON, JSON5 or logfmt, with key selection and null handling. `PercentCodec` is
  now public.
- **Default key values:** a new `DEFAULTS` source for values that belong on every event,
  such as a commit id. The `rainbowgum-keyvalues-contributor` module (experimental) seeds it
  from `logging.keyvalues.contributor.defaults`. `logging.keyvalues.disabled` turns off
  chosen sources.
- **Level file:** with `logging.simpleprops.levelFile=watch`, simple props polls
  `level.properties` and applies level changes without a restart. Group levels in the file
  win over every other source. The file is refused while it or its directory is writable by
  group or others, and an invalid edit is rejected while the previous levels are kept.
- **Short keys in simple props:** keys in `logging.properties` may leave off `logging.`, so
  `level.com.myco=debug` works. A `java.util.logging` file of the same name is detected and
  reported instead of being silently prefixed.
- **Groups for change and caller:** `logging.change.logger.<group>` and
  `logging.caller.logger.<group>` accept groups, so logger names that cannot be written as
  keys (environment variables, `$` in class names) can go in a group's value.
- **Catching configuration mistakes:**
  - `logging.alerts.fail=error|warning` fails startup when an alert at that level was
    recorded.
  - `logging.alerts.unusedKey` controls how unread keys are reported.
  - `logging.debug=help` turns on full debug output and fails on warnings.
  - A key that is never read is reported, with a suggestion when it is close to a real key
    or uses the old 0.14 encoder, output or publisher layout.
  - An unknown output, encoder or publisher scheme suggests a similarly spelled one and
    names the module to add.
- **`LogConfig.reporter()`:** the reporter lives on the config. Modules register the
  properties they read, and the report lists each with its value and the packages that read
  it, plus a `Globals:` block of resolved global settings.
- **`LogConfig.globals()`:** global settings resolved once, each with a `LogConfig.Builder`
  method (`changeMode`, `ansiMode`, `appenderLock`, `threadLocal`, `optimize`,
  `keyValuesDisabled`). Every global is parsed before any error is thrown, so all mistakes
  are reported together.
- **`%highlight` options:** the pattern encoder accepts Log4j2 style
  `%highlight(%-5level){ERROR=red bold, WARN=red}`. Without options it uses Logback's colors.
- **Scoped key values are no longer experimental.** `rainbowgum-scopedkeyvalues-api` and
  `rainbowgum-scopedkeyvalues` are ready to depend on.
- **`@EnumAlias`:** enum property aliases such as `true` and `false` are documented on the
  constant they select, and the build checks them against each enum's parser.

## Breaking changes

### Property layout

Encoder and output keys moved under their appender, and publisher keys under their route,
with each type's settings under its URI scheme:

```properties
logging.appender.console.encoder.uri=json5
logging.appender.console.encoder.json5.prettyPrint=spacing
logging.appender.console.output.uri=stdout
logging.appender.console.output.stdout.stream=follow

logging.route.main.publisher.uri=async
logging.route.main.publisher.async.bufferSize=2048
```

| 0.14 | 0.15 |
| --- | --- |
| `logging.appender.{name}.encoder` | `logging.appender.{name}.encoder.uri` |
| `logging.encoder.{name}.*` | `logging.appender.{name}.encoder.{scheme}.*` |
| `logging.appender.{name}.output` | `logging.appender.{name}.output.uri` |
| `logging.output.{name}.*` | `logging.appender.{name}.output.{scheme}.*` |
| `logging.route.{name}.publisher` | `logging.route.{name}.publisher.uri` |
| `logging.publisher.{name}.*` | `logging.route.{name}.publisher.{scheme}.*` |
| `logging.global.change=true` | `logging.change.mode=on` |
| `logging.change.{logger}` | `logging.change.logger.{logger}` |
| `logging.caller.{logger}` | `logging.caller.logger.{logger}` |
| `logging.global.ansi.disable` | `logging.global.ansi.mode` (`auto`, `on`, `off`) |
| `logging.global.appender.reentrantLock` | `logging.global.appender.lock` (`auto`, `reentrant`, `synchronized`) |
| `logging.global.threadlocalDisabled` | `logging.global.threadLocal` (`allow`, `forbid`) |
| `logging.jfr.alerts.enabled` | `logging.jfr.alerts.mode` (`off`, `on`) |

Old keys are not read. Running once with `-Dlogging.debug=help` reports every key that
was not read, and for the old encoder, output and publisher layouts it names the new key.

### Behavior

- **Strict booleans:** boolean properties accept only `true` or `false`, case-insensitive.
  Before, `file.append=yes` silently meant false and truncated the log file.
- **`logging.global.appender.lock=auto`**, the default, uses a reentrant lock before JDK 24,
  so on JDK 21 to 23 a requested synchronized appender now gets a reentrant lock unless the
  lock is set to `synchronized`.
- **ANSI:** `logging.global.ansi.mode` has one meaning for every reader. Before, `false`
  meant "detect" to core but "force" to the pattern encoder. Spring's
  `spring.output.ansi.enabled=always` now forces color.
- **Default console output:** the `rainbowgum` aggregate no longer includes
  `rainbowgum-pattern`, so the console uses TTLL, which writes the same colors but prints
  logger names in full. TTLL also shows key values by default. Spring Boot and Micronaut
  still bring in the pattern module.
- **`%highlight` without options** now uses Logback's colors (warn red, not bold red). The
  default pattern keeps warn bold red.
- **Routes** that set levels only for some loggers now default other loggers to INFO
  instead of ALL.
- **`rainbowgum-simple-props`:** keys without the `logging.` prefix are now accepted and
  prefixed by default; `logging.simpleprops.strict` still selects `fail`, `alert` or `off`.
- **`rainbowgum-jansi`** only installs the JAnsi console wrapper; it no longer replaces the
  console encoder.
- **Encoders:** Logstash, ECS, GELF and logfmt move a key value named like one of their
  fields into a nested `keyValues` object or a `keyValues.` prefix instead of writing a
  duplicate field. logfmt keys with characters logfmt does not allow are percent encoded
  instead of replaced with `_`.
- **Lists and maps in properties:** `=` is now part of a list element, and one empty element
  is dropped at each end. Maps can also be written as `key.keys=a,b` with `key.a` and
  `key.b`.

### API

- The core `json` formatter is renamed `json5` (`Json5Formatter`, `Json5FormatterBuilder`);
  its `levelFormatter` option is replaced by `prettyPrint`.
- `JansiLogFormatter` and `AbstractStandardEventFormatter.SCHEMA` are removed; use
  `TTLL.SCHEMA`.
- `LogFormatter.Builder.encodedKeyValues` and the logfmt key values methods are replaced by
  `keyValues()` and `keyValues(Consumer)`. The Logback `%X` style formatter moved to the
  pattern module.
- `TTLL.ColorTheme` is a sealed interface instead of an enum; its constants are unchanged.
- Pattern `CacheType.DISABLED` is now `OFF`.
- `LogReporter` is reached through `LogConfig.reporter()`, with rendering choices in
  `LogReporter.Options`.
- `IgnoreChangePublisher` is removed; the change publisher checks `logging.change.mode`.
- `LogConfig.Builder` boolean methods for the appender lock and thread locals are replaced
  by `appenderLock(AppenderLock)` and `threadLocal(ThreadLocalMode)`.
- `JfrAlertListener.enabled()` is now `mode()`.
- `@LogConfigurable` prefixes must be lowercase package-like names under `logging.`, and
  property names that differ only by case are rejected.

## Fixes

- JFR events crashed with `LinkageError` and alert events were not recorded when the
  recording started with the JVM (`-XX:StartFlightRecording`), on JDK 21 through 27.
- Level file edits now reach existing loggers, and a changed group level now applies.
- `%red(%msg)%n` printed a literal `%n`: a keyword directly after a pattern group is now
  parsed.
- Reports listed `SYSTEM_PROPERTIES` twice.
- Many user guide problems found by black-box QA were fixed.

## Under the hood

- Percent encoding of UTF-8 key values no longer allocates and is about three times faster.
- The pattern encoder's logger abbreviation cache is a `ConcurrentHashMap` instead of a
  locking port of Logback's cache.
- Two Rainbow Gum instances in one JVM no longer overwrite each other's global settings:
  the process-wide statics are gone.
- Coverage is reported by a self-hosted JaCoCo report instead of Codecov.
- The examples build as part of the main reactor, with a new simple props example.
- Annotation processor tests moved to `test/rainbowgum-test-apt`, off the build's critical
  path.
