# Rainbow Gum 0.16.0

This release renames the remaining negative and boolean style properties to modes and allow
lists, makes default key values stable, and adds formatter post processors for systemd journal
and single line output. The JUL style facades (`java.util.logging`, System.Logger and JBoss
Logging) now format messages the way the JDK does and follow the global Rainbow Gum after it
starts. Several properties were renamed; see [Breaking changes](#breaking-changes). The
0.15.1 patch release had no notes of its own, so its changes are listed
[at the end](#also-in-0151).

## New features

- **Formatter post processors:** a `LogFormatter.PostProcessor` rewrites the finished text
  of an event, including substituted arguments and stack traces, for any encoder backed by a
  formatter. They are chosen by name and run in order:

  ```properties
  logging.appender.console.encoder.postProcessors=crlf,journald
  ```

  `journald` prefixes every line with its syslog severity and `crlf` escapes line breaks
  inside an event. Custom ones are registered with `PostProcessor.register` under a name of
  their own. The user guide shows how a systemd service can log to the console and let the
  journal handle rotation and retention.
- **Default key values are stable.** `rainbowgum-keyvalues-contributor` is no longer
  experimental. The user guide shows a configurator that adds a git commit id from a class
  generated at build time by the templating-maven-plugin.
- **`logging.keyvalues.sources`:** an allow list of key value sources. Absent selects every
  source and an empty value selects none. A facade's own context store, such as the SLF4J
  MDC, is always used for that facade's own events. The report prints the selected sources
  in merge order.
- **`logging.pattern.config.{name}.ansi`:** takes the same values as
  `logging.global.ansi.mode` (`auto`, `on`, `off`). `auto` follows the global mode, and a
  global `off` always wins. The global mode now also applies to a `PatternConfig` registered
  in code, which used to ignore it.
- **`logging.pattern.mode`:** `console` (the default) makes the pattern encoder the console
  default, and `explicit` uses it only where an encoder names it.
- **`logging.jul.level`:** decides the `java.util.logging` root level. `sync` (the default)
  copies Rainbow Gum's root level, `none` leaves it alone, and a level sets it. `all` passes
  every event to Rainbow Gum, so a logger configured more verbose than the root, such as
  `logging.level.com.example=debug` with an `info` root, logs its JUL events, at the cost
  of a `LogRecord` for every event.
- **`logging.messageFormat.style`:** chooses how JUL style facades apply `MessageFormat`,
  named after the implementations that behave that way:
  - `jdk` (the default, alias `jboss`): `MessageFormat` runs only when the message has an
    argument index, and a `Throwable` argument is only an argument.
  - `log4j2` (alias `logback`): `MessageFormat` runs whenever there are arguments, and a
    trailing `Throwable` is also the event's throwable.

  A malformed pattern still logs the raw message with `[MessageFormat failed: reason]`.
- **JUL style facades follow the global Rainbow Gum.** The System.Logger finder, the JBoss
  Logging provider and the JUL LogManager subscribe to `RainbowGum.onGlobalChange`, so a
  logger created before Rainbow Gum starts picks up its properties once it does.
- **Nested property sources:** `LogProperties.AbstractNested` is a skeleton for sources such
  as TOML, HOCON or YAML, where a logger name in a key (level, route level, change and
  caller) has to be looked up as one quoted member. `rainbowgum-test-nested-properties` has
  TOML, HOCON and Helidon Config examples.
- **`root` alias:** `logging.level.root` is the same as `logging.level`, as in Spring Boot,
  and likewise for route level, change and caller keys.
- **`RainbowGum.ofOrNull()`:** like `of()`, except that it returns null on the thread that
  is starting the global Rainbow Gum.
- **JFR namespaces:** log events are `io.jstach.rainbowgum.log.{Trace,Debug,Info,Warn,Error}`
  in the `Rainbow Gum/Log` category, and alerts are
  `io.jstach.rainbowgum.alert.Alert{Trace,Debug,Info,Warn,Error}` in `Rainbow Gum/Alert`, so
  each family can be selected with a namespace glob or `jfr print --categories`.
- **Missing module messages:** when a scheme comes from a module that is on the path but
  whose configurator was not loaded, the error now says so and suggests
  `LogConfig.Builder.serviceLoader()` instead of telling you to add the dependency.

## Breaking changes

### Properties

| 0.15 | 0.16 |
| --- | --- |
| `logging.keyvalues.disabled` (sources to turn off) | `logging.keyvalues.sources` (sources to use) |
| `logging.keyvalues.contributor.defaults` | `logging.keyvalues.defaults` |
| `logging.pattern.config.{name}.ansiDisabled` | `logging.pattern.config.{name}.ansi` (`auto`, `on`, `off`) |
| `logging.pattern.disable=true` | `logging.pattern.mode=explicit` |
| `logging.jul.level.disable=true` | `logging.jul.level=none` |

Old keys are not read. Running once with `-Dlogging.debug=help` reports every key that was
not read.

### Behavior

- **JUL style `MessageFormat`:** the default is now the JDK's. `MessageFormat` runs only
  when the message has an argument index, so `"It's done"` logged with an argument keeps its
  apostrophe. A trailing `Throwable` argument is formatted as an argument instead of
  becoming the event's throwable, which used to leave its placeholder unformatted. Set
  `logging.messageFormat.style=log4j2` for the previous behavior.
- **`RainbowGum.builder(Consumer)`** now uses the service loader, like
  `RainbowGum.builder()`, so it finds installed modules. `LogConfig.builder()` still does
  not unless `serviceLoader()` is called.
- **Post processor names:** `journald` and `crlf` are registered when the `LogConfig` is
  created, and registering does not replace a name, so a custom post processor needs a name
  of its own.
- **JFR event names** moved to the namespaces above. Recordings or settings that select the
  old names need updating.
- **`rainbowgum-json`** writes unicode escapes with lowercase hex (`\u001b`), the same as
  core's JSON5 and logfmt encoders.

### API

- `LogConfig.Builder.keyValuesDisabled(Set)` and `LogConfig.Globals.keyValuesDisabled()` are
  now `keyValueSources`, defaulting to every source.
- `KeyValuesContributor.Source.Standard.clearWhenDisabled()` is now `clearWhenUnselected()`.
- `DefaultKeyValues.PROPERTY_PREFIX` is replaced by `DefaultKeyValues.DEFAULTS_PROPERTY`.
- `PatternConfig.ansiDisabled()` is now `ansi()`, returning `LogConfig.Globals.AnsiMode`,
  and the builder method is `ansi(AnsiMode)`.
- `RainbowGum.onGlobalChange` subscribers now also receive `null` when the global Rainbow
  Gum is removed.

## Fixes

- When the System.Logger finder started Rainbow Gum and something it loaded, such as a
  properties provider building Helidon Config, asked for a System.Logger on the same
  thread, startup failed with "tried to log too early". Those events are now held until
  Rainbow Gum is ready.
- Non-ASCII characters in list, map and URI query values were decoded byte by byte, so
  `logging.group.g=café.Ünïcode` never matched and its level silently did not apply.
- `%logger{1}` split an emoji at the start of a segment, writing a lone surrogate (`a.?.b`).
  Logback 1.5.37 and Log4j2 2.26.1 have the same bug.
- Global change notifications are delivered in order, outside locks, and a failing
  subscriber no longer stops the others.
- SLF4J loggers looked up while no Rainbow Gum is bound now follow the next one bound.

## Documentation

- [`doc/logger-name-edge-cases.md`](../logger-name-edge-cases.md) compares what Logback,
  Log4j2 and Rainbow Gum do with unusual logger names.
- [`doc/system-logger-message-format.md`](../system-logger-message-format.md) compares how
  System.Logger implementations format `MessageFormat` style messages.
- The user guide has note, important and warning callouts, and warns against
  `slf4j-jdk-platform-logging`, which formats System.Logger messages twice
  ([qos-ch/slf4j#498](https://github.com/qos-ch/slf4j/pull/498)), and against putting
  sensitive data in key values, which the default format logs.
- The user guide states which entry points use the service loader.

## Also in 0.15.1

- Logger names that are not valid property keys, such as names ending in a dot or the names
  Testcontainers makes for images with a digest, no longer break `getLogger` or fall back
  to INFO with an alert ([#752](https://github.com/jstachio/rainbowgum/issues/752)).
- The async publisher has explicit overload handling: `overflow=drop` discards instead of
  blocking when full, and `discardThreshold` with `discardLevel` reserves slots for
  higher-priority events. Blocking stays the default, and discarded events are counted as
  warnings in `events.discarded`.
- OTLP records match the OpenTelemetry Logback and Log4j appenders, and the OTLP output
  allocates about 70% less.
- With no JFR recording running, JFR outputs no longer allocate.
- Trailing whitespace in typed property values is ignored.
- Unused key suggestions name the key the way the source spells it, for example an
  environment variable.
