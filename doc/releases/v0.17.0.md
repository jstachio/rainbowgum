# Rainbow Gum 0.17.0

This is likely the last feature release before 1.0.0. It adds an LTSV encoder and a plain JSON
encoder to core, route filters for throttling, deduplicating and remapping events, and much
better feedback on configuration: a debug report of every property that was read, and startup
now fails by default on configuration mistakes such as a misspelled key. Properties a component
marks as sensitive are redacted and refused in URIs. Several defaults changed; see
[Breaking changes](#breaking-changes). The 0.16.1, 0.16.2 and 0.16.3 patch releases had no
notes of their own, so their changes are listed [at the end](#also-in-0161-0162-and-0163).

## New features

- **LTSV encoder:** the `ltsv` encoder scheme writes each event as one line of tab separated
  `label:value` fields ([ltsv.org](http://ltsv.org)) with logfmt's field names. Values are
  never quoted, so every event stays on one line. `columns` lists the fields to write first,
  by position and without labels, and the rest follow with their labels:

  ```properties
  logging.appender.console.encoder.uri=ltsv
  logging.appender.console.encoder.ltsv.columns=time,level,logger,thread,msg
  ```

  `timestamp`, `level` and `logger` take TTLL's choices, and colors work like TTLL's. The user
  guide shows a systemd journal setup and `tabs -2` for reading it in a terminal.
- **Plain JSON encoder:** `logging.appender.console.encoder.uri=json` writes the same fields as
  `json5` as plain JSON, with its own properties under `encoder.json.`. Like `json5` it is a
  convenience with one fixed set of fields; `rainbowgum-json` has the ECS, GELF and Logstash
  schemas.
- **Route filters:** a `LogRouter.Router.Filter` drops or changes a route's events before its
  publisher gets them. Filters are registered by name with `Router.Filter.register`, usually
  from a configurator, and selected in order with `logging.route.{name}.filters`. Three are
  built in, configured under `logging.route.{name}.filter.{filter}.`:
  - `throttle` keeps a burst and then a rate of events per second, like Log4j2's
    `BurstFilter`.
  - `dedupe` drops a message once it repeats too often, like Logback's
    `DuplicateMessageFilter`.
  - `remap` moves events from one level to another, optionally for some loggers only.

  ```properties
  logging.route.console.filters=throttle
  logging.route.console.filter.throttle.rate=20
  ```

  `throttle` and `dedupe` leave events at `WARNING` and above alone by default. Dropped events
  are counted in `events.filtered`, and throttled and deduplicated ones also in
  `events.throttled` and `events.deduplicated`. `Router.Builder.filter` adds filters in code.
- **Rewriting events:** `LogEvent.withLevel(event, level)` returns the event at another level
  and `LogEvent.rewrite(event, rewriter)` replaces its message, key values or throwable,
  without formatting or copying the original. When a filter moves an event to a level the
  route does not enable, the route drops it.
- **Properties that were read:** a new `READ_PROPERTIES` report section lists every key that
  was read, in key order: a set key with its value and where it came from, an unset key by
  itself. A component's settings sit together, so one it does not read stands out by its
  absence. URI query parameters are listed as the keys they stand for. `logging.debug=all`
  and `help` print it at startup. The Spring Boot Actuator info contributor leaves it out.
- **Unread URI query parameters are reported.** `./logs/app.json?maxFileSize=10MB` chooses the
  plain file output, which has no `maxFileSize`, and used to lose rolling silently. A query
  parameter the chosen component does not read is now a warning.
- **Better suggestions for misspelled keys:** `logging.levle.com.example` and
  `logging.levels.com.example` suggest `logging.level.com.example`, and likewise for route
  level, change and caller keys. A key that differs from the suggestion only in a component's
  name or type, such as an appender left out of `logging.appenders`, is information instead
  of a warning.
- **`logging.alerts.fail=config`:** the new default. It fails startup on warnings and errors
  about configuration: a misspelled key, an unread URI query parameter, a simple-props strict
  alert, a refused level file and a level that cannot be parsed. Problems while logging, such
  as an appender failing to write, are reported but do not stop the application. A
  configuration source of your own marks its alerts with `LogAlerts.config(...)`.
- **Sensitive properties:** a `@LogConfigurable` factory parameter marked
  `@LogConfigurable.SensitiveParameter` is read through `LogProperty.sensitive()`. Its value is
  redacted in errors, converter exceptions and the read properties report, and the component
  fails to build if its URI query sets it. The OTLP output's `headers` are marked.
- **Thread fields:** the `json5`, `logfmt` and `ltsv` encoders have a `thread` property:
  `name`, `id`, `both` or `none`. TTLL's `thread` gains `both` (`[7][main]`) and
  `name_or_id`, which writes the id when the name is empty, as it usually is for a virtual
  thread.
- **`logging.simpleprops.envPrefix`:** sets the environment variable prefix from the base
  `logging.properties` instead of code.
- **Content types:** the `json5` encoder reports `application/json5`, and `json`
  `application/json`.
- **Javadoc search finds property keys.** Searching for `logging.alerts.fail`, or part of a
  key, finds where it is documented, and the Search Tags page lists every key.

## Breaking changes

### Properties

| 0.16.0 | 0.17.0 |
| --- | --- |
| `logging.messageFormat.style` | `logging.messageformat.style` (changed in 0.16.1) |
| `logging.alerts.fail` defaults to `off` | defaults to `config` |
| `thread` of `json5` and `logfmt` defaults to the name | defaults to `both` |

Every segment of a property name but the last is lowercase, like a package name, and a test
now checks it. `logging.messageFormat.style` was the one that was not.

### Behavior

- **Startup fails on configuration mistakes by default.** A misspelled key with a suggestion,
  an unread URI query parameter, simple-props `strict=alert` errors and a refused level file
  now stop startup with an `IllegalStateException`. Set `logging.alerts.fail=off` for the
  previous behavior, or `warning` to also fail on problems while logging, for example in CI.
- **`json5` and `logfmt` write `threadId` and `threadName`** instead of `thread`. Set
  `thread=name` for the previous field.
- **Lines end with `\n` on every platform** (since 0.16.2), which only changes output on
  Windows. Formatters, stack traces and the pattern `%n` used `System.lineSeparator()`. Set
  the system property `logging.global.lineSeparator` to `crlf` or `platform` for the previous
  behavior.
- **URIs in diagnostics hide every query value.** Reports and error messages show a URI's path
  and parameter names but no values, and the read properties report shows each parameter that
  was read on its own.
- **Sensitive properties cannot be set in a URI query.** OTLP `headers` in
  `otlp:///?headers=...` fail the build; set them as their own properties.
- **Environment variable prefixes** must end with an underscore and must not start with
  `HTTP_`, both in `logging.simpleprops.envPrefix` and `SimpleProperties.Builder.envPrefix`.
- **Frozen events:** `LogEvent.message()` on an event frozen for an async route returns the
  unformatted message, the same as before freezing. `formattedMessage` is unchanged.
- **`file:./app.log` and `rolling:app.log`** fail with a message showing the forms that work,
  and `rolling:///./logs/app.log` is relative to the working directory, like `file:///./`.

### API

- `AbstractRouter`, `RouterFactory` and `Router.Builder.factory` are removed. Code that used
  `factory(RouterFactory.of(function))` uses `filter(function)` instead.
- `LogAlerts.FailLevel` gains `CONFIG` and `LogReporter.Section` gains `READ_PROPERTIES`, so a
  `switch` over either needs a new case.
- `LogProperty.Result.Missing` gains a `sensitive` component. The three argument constructor
  remains.

## Fixes

- A URI without a scheme, such as `./app.log?append=false` or `stdout?stream=follow`, lost its
  query, so the component never saw the parameters.

## Documentation

- The user guide is also published as Markdown, `overview.md`, next to the javadoc, with
  `llms.txt` and a guide for agents migrating a project from Logback.
- The user guide says not to put credentials in a URI, documents custom properties sources,
  and covers relative paths, parent directories and `fileNamePattern` for file outputs.
- The README has an Integration section linking the facade and framework docs and listing the
  supported formats.

## Also in 0.16.1, 0.16.2 and 0.16.3

- **0.16.1:** `logging.messageFormat.style` was renamed `logging.messageformat.style`. A logger
  set to `OFF` stays off, and existing loggers follow, when the global Rainbow Gum is replaced,
  as Jooby's integration does.
- **0.16.2:** Windows. Absolute file output URIs, `logging.file.name` with a drive letter or
  backslashes, and the rolling and JFR outputs work on Windows, and lines end with `\n` on
  every platform. CI now builds on Windows.
- **0.16.3:** an appender whose encoder fails to build closes its output, so a file handle no
  longer leaks. Published poms no longer have broken project and SCM links. An event with
  caller info and no message no longer writes `null`.
