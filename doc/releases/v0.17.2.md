# Rainbow Gum 0.17.2

A patch release of fixes, most of them found by code and security reviews: the global
Rainbow Gum binds atomically, events logged before it is bound are bounded, appenders survive
reentrant logging, a failing output no longer prints a stack trace per log call, and file and
rolling outputs keep their events when reopening or rotating fails. Two behaviors changed; see
[Breaking changes](#breaking-changes). 0.17.1, a security release, had no notes of its own, so
its changes are listed [at the end](#also-in-0171).

## New features

- **`logging.global.shutdownHook`:** set it to `false` to stop the global Rainbow Gum
  registering a JVM shutdown hook that closes it. JVM shutdown hooks run concurrently in no
  set order, so events other hooks log after Rainbow Gum's has run are lost, except errors,
  which are echoed to standard error. An application or framework that closes Rainbow Gum
  itself as the last step of its own shutdown can now opt out. It defaults to `true`.
- **`logging.global.queue.size`:** the system property for how many events are queued while no
  Rainbow Gum is bound. See below.

## Breaking changes

### Behavior

- **The disruptor no longer takes over `async`.** With `rainbowgum-disruptor` on the class
  path it was the publisher for every route asking for `async`. It is now used only by a
  route that asks for it:

  ```properties
  logging.route.{name}.publisher.uri=disruptor:///
  ```

  It was experimental, and taking over the scheme was a bug.
- **The queue for events logged while no Rainbow Gum is bound is bounded.** That is before one
  is bound, or after it is closed. The queue had no limit and kept events unfrozen, so their
  arguments stayed alive and were formatted later on another thread. Events are now frozen
  when queued, and at most `logging.global.queue.size` events are kept (default 1000). The
  rest are dropped, and binding the next Rainbow Gum reports how many as one warning alert.
- **`crlf` escapes more.** The opt-in `crlf` post processor escaped only CR and LF, so an
  escaped line break could not be told from a `\n` typed in the logged text, and logged text
  could still move the cursor, set the terminal title or write the clipboard. It now also
  doubles backslashes and escapes every other control character except tab, including ESC,
  DEL, C1 controls such as NEL, and U+2028 and U+2029, as `\uXXXX`. ANSI colors from the
  formatter are escaped too, so turn colors off with `crlf`.

### Deprecations

- `BlockingQueueAsyncLogPublisher` is deprecated for removal. It is an example and never
  meant for production; the built-in `async` publisher is the one to use.

## Fixes

- **Binding the global Rainbow Gum is atomic.** `Builder.set()` set a supplier and then started
  it as a separate step, so another thread binding in between made it start a different
  Rainbow Gum and throw. It now starts and binds its own in one step. A replacement that fails to start leaves the previous
  one bound and is closed.
- **Reentrant logging no longer corrupts the outer event.** An argument whose `toString()`
  logs runs while the appender encodes the outer event, and the nested append reused and
  cleared the same buffer, so the outer line came out glued to the inner one. A reentrant
  append now gets a fresh buffer.
- **One alert per run of append failures.** Every failed append raised an error alert, and
  alerts print with their stack trace, so a full disk printed one stack trace per log call. A
  failing output is an unhealthy system that needs a restart or redeploy, and the extra
  output only widens the damage. Now the first failure is alerted, every failure is still
  counted in `events.failed`, and the next successful append reports how many more failed.
- **A failed reopen keeps the current file.** `reopen()` closed the current file before
  opening the new one, so when opening failed, for example after logrotate moved the file
  into a directory the process can no longer write, every later event was silently ignored.
  It also lost buffered output, and `append=false` truncated on every reopen instead of only
  the first open.
- **Rolling files keep events when rotation fails.** The event that triggered a failed
  rotation is written to the active file, a failed batch carries on event by event, and
  a failed rotation is retried once the active file has doubled in size instead of on every
  write, which with gzip archives compressed the same growing file again and again.
- **History cleanup leaves files it did not write alone.** A file such as
  `app.log.99999999999` in the log directory failed the rolling output's start. Indexes that
  are zero, zero padded or too large, directories and symbolic links are now skipped and
  reported, and the archive size cap does not follow links.
- **Prudent file writes complete.** A channel write that wrote only part of an event lost
  the rest. It is now finished while the file is still locked.
- **The disruptor publisher starts and closes its appenders.** It never started them, and
  closing it neither wrote the events still in the ring nor closed the appenders, after which
  a log call blocked forever once the ring was full.
- **`throttle` survives the clock stepping back.** It measures time with event timestamps, so
  after an NTP correction or a VM resume every throttled event was dropped until the clock
  caught up. Rates above a billion per second no longer turn throttling off.
- **JSON doubles are valid JSON.** Non-finite values were written with two sets of quotes, and
  zero was written as a string. Finite values are always numbers and `NaN` and the infinities
  are strings.

## Documentation

- `SECURITY.md` says which versions are supported, how to report a vulnerability privately,
  and what counts as one: configuration is trusted, logged content is not, and a network
  output's endpoint is trusted with the log records but not with the application.

## Also in 0.17.1

A security release. Diagnostics no longer leak credentials, and output that logged content
controls is processed in linear time.

- **logfmt, LTSV and `crlf` escape in linear time.** They shifted the rest of the buffer for
  every escaped character, so 512 KiB of newlines took seconds per event.
- **Credentials stay out of diagnostics.** URIs with a scheme but no authority, such as
  `http:user:pass@host` and JDBC URLs, are redacted, and so are credential URIs that do not
  parse. A malformed URI's conversion error no longer quotes it. `LogProperty.parseURI` gives
  custom components the same value-safe parsing.
- **OTLP:** the endpoint and headers are validated at startup, naming the bad header but
  never its value. Header values never reach error messages, responses are read up to 64 KiB
  and escaped before they appear in alerts, a long error message in a response no longer
  overflows the stack, and redirects are never followed.
- **opentelemetry-api 1.67.0** for GHSA-ccrj-gw8r-854m, which `rainbowgum-opentelemetry`
  brings in as a compile dependency.
- **GraalVM native image:** Rainbow Gum is no longer started while an image is built with only
  `System.Logger` (no SLF4J) on the class path, which failed the build.
- **Breaking:** `LogOutputRegistry.output(String)` is removed. It handed out an output its
  appender owns, outside the appender's locking and lifecycle. Keep your own reference
  instead, for example by registering a scheme or building the appender with the output.
