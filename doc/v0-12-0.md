# Rainbow Gum 0.12.0

This release's headline is **JDK Flight Recorder integration**: a new `LogOutput` that
commits log events as JFR events, with a URI-based file destination that starts and
owns its own Flight Recorder session, no `-XX:StartFlightRecording` flags required.
Alongside that: a `java.util.logging.LogManager` replacement for Helidon-style JUL
bridging, a native JBoss Logging module, an experimental `ScopedValue`-backed request
context, and a real fix to an encoder-resolution bug that had been silently blocking
any output from ever having its self-supplied encoder overridden.

## New module: `rainbowgum-jfr`

Commits each log event as a JFR event instead of writing bytes anywhere, one event type
per level so each can be independently enabled, thresholded, or given a stack trace
setting through a normal Flight Recorder configuration - not through Rainbow Gum
properties:

```properties
logging.appenders=myappender
logging.appender.myappender.output=jfr:///
```

Give the output's own URI a real file path instead of the bare `jfr:///` and it starts
and owns a Flight Recorder session writing directly to that file for the process's
lifetime - the simpler alternative to wiring JFR in at the JVM level, and worth reaching
for first:

```properties
logging.appender.myappender.output=jfr:///var/log/myapp.jfr
```

The module can also commit Rainbow Gum's own alerts (an appender failing to write, an
async publisher's queue overflowing) as JFR events, opt-in via
`logging.jfr.alerts.enabled=true`. Alerts use their own separate JFR event type family
so they never get confused with genuine application log events in a recording.

## New module: `rainbowgum-jul-logmanager`

An opt-in `java.util.logging.LogManager` replacement, built for Helidon-style JUL
bridging, with GraalVM native-image support baked into the module itself (no manual
reflect-config needed).

## New module: `rainbowgum-jboss-logging`

Native JBoss Logging integration alongside the existing SLF4J/JCL/JUL bridges.

## New (experimental): `ScopedValue`-backed request context

`rainbowgum-scopedkeyvalues`/`rainbowgum-scopedkeyvalues-api` (renamed from
`rainbowgum-scoped-key-values`) provide an MDC alternative for JDK 25+ backed by
`java.lang.ScopedValue` instead of `ThreadLocal`.

## New: `AppenderType.AUTO_DETECT` and `logging.global.optimize`

Platform-gated, opt-in defaults that pick better-performing appender/encoder strategies
automatically depending on whether the JVM is a normal JVM or a GraalVM native-image
binary - documented in the GraalVM Native Image section of the overview.

## Fixed: outputs can no longer trap their own encoder

An output that implemented `LogEncoder` itself used to win over any explicitly
configured encoder unconditionally, with no way to override it at all. `LogOutput.
ProvidesEncoder` replaces that: an output now declares whether its own encoder is
mandatory (no override allowed, misconfiguring one is a startup failure) or just an
overridable default.

## Root-cause-first exception formatting

New `%rEx`/`%rootException` pattern keyword, and nested configuration failures now
render root-cause-first as well.

## Under the hood

- Unified appender construction onto a single `LogAppender.Builder` path - programmatic
  and property-driven configuration no longer diverge.
- `KeyValues` internals reworked: removed low-level index-based access, fixed a real
  infinite-loop bug and a quadratic merge, added a lazy composite implementation.
- Removed `LogResponse`/`LogComponent`; `LogOutput#reopen()` is now `void` and reports
  failures as alerts instead.
- GraalVM native-image: new AOT cache (JEP 483) and native-image smoke-test modules, CI
  now tracks the latest GraalVM, `native-image.properties` shipped so build-time-init
  flags aren't manual.
- errorprone and NullAway turned on across nearly every module; checkerframework null
  analysis extended to the rest of the codebase.

## Docs

New `why_rainbowgum_is_better.md` with real, measured comparisons against Logback,
Log4j2, and tinylog: GraalVM native-image speed and memory, disabled-level logging
cost, configurable locking strategy, test coverage claims, log rotation, and metrics.
Also new: `development.md`, `build.md`, `release.md` for contributors.

## Breaking changes

- `rainbowgum-scoped-key-values`/`rainbowgum-scoped-key-values-api` are now
  `rainbowgum-scopedkeyvalues`/`rainbowgum-scopedkeyvalues-api` (still experimental).
- `LogOutput#reopen()` is now `void` (was previously returning `LogResponse`, which is
  removed); failures are reported as alerts instead.
- `KeyValues`' low-level index-based accessors are removed.
